# API

Base path: `/api/v1/`. OpenAPI schema is auto-generated by drf-spectacular,
never hand-maintained — browse it live at `/api/v1/schema/` (raw) or
`/api/v1/docs/` (Swagger UI) once the backend is running.

## Implemented

Billing endpoints (`/visits/{id}/invoice/`, `/invoices/`, `/invoices/{id}/items/`,
`/invoices/{id}/payments/`) existed through Phase 4 and were removed on
2026-09-08 per explicit user decision — see CLAUDE.md §17.

| Resource | Path | Notes |
|---|---|---|
| Health check | `GET /health/` | Liveness + DB connectivity. `AllowAny` — one of two endpoints not behind auth. |
| Login | `POST /auth/token/` | Email + password → access/refresh pair. `AllowAny`. Audits `login_success`/`login_failed` either way. |
| Token refresh | `POST /auth/token/refresh/` | Rotates the refresh token; old one is blacklisted. |
| Logout | `POST /auth/logout/` | Blacklists the given refresh token. Auth required. |
| My profile | `GET /users/me/` | Any authenticated user — no module permission needed for your own record. |
| List users | `GET /users/` | Requires `users.view` — System Admin / Hospital Admin only per `docs/RBAC.md`. Demonstrates the RBAC 403 deny path. |
| Departments | `GET /departments/` | Reference data (hospital-scoped) — any authenticated user, no dedicated module. |
| Patients | `GET/POST /patients/`, `GET/PUT/PATCH /patients/{id}/` | Search via `?search=`. No `DELETE` — nobody is granted delete on Patient Records (docs/RBAC.md); "delete" in the UI is `PATCH is_active: false`, a soft-delete (`patients.edit`). The default `GET /patients/` list excludes deleted patients; `?include_deleted=true` includes them. A deleted patient is still fetchable directly by id (so the detail/restore page works), and is rejected as the `patient` on both `POST /queue/check-in/` and `POST /appointments/` until restored. Hospital-scoped: a patient outside your hospital 404s, not 403 (doesn't reveal existence). |
| Insurance | `GET/POST /patients/{id}/insurance/` | NHIS or private, nested under the patient. |
| Insurance eligibility | `GET /patients/{id}/insurance/{id}/verify/` | Calls the mock `InsuranceProviderInterface`. Nothing persisted. |
| Appointments | `GET/POST /appointments/`, `GET/PUT/PATCH/DELETE /appointments/{id}/` | Filter via `?department=` `?doctor=` `?date=`. `DELETE` cancels (sets `status=cancelled`) — the row is never removed, since cancellations are reporting-relevant. Status now includes `checked_in` (Phase 2). |
| Allergies | `GET/POST /patients/{id}/allergies/`, `PATCH /patients/{id}/allergies/{id}/` | Structured (`allergen`/`reaction`/`severity`), nested under the patient. `PATCH` is for `is_active=false` deactivation only — no other fields are editable, no `DELETE`. |
| Queue check-in | `POST /queue/check-in/` | Creates a `Visit` + `Queue` entry together (and, if `appointment` is given, moves it to `checked_in`). Rejects a second active visit for the same patient. |
| Queue | `GET /queue/`, `GET/PATCH /queue/{id}/` | Excludes completed/cancelled by default; `?department=` `?status=` filter. Sorted emergency-first, then queue number. `PATCH` only accepts `status`/`doctor`, with transition validation (`waiting→in_consultation→completed`, either state `→cancelled`). No `POST`/`DELETE` — see check-in above and cancel-via-`PATCH`. |
| Visit detail | `GET /visits/{id}/` | Header info (patient/department/status) for the clinical workspace. |
| Vitals | `GET/POST /visits/{id}/vitals/` | One visit can have more than one reading. BMI computed server-side, never client-supplied. |
| Consultation | `GET/POST/PATCH /visits/{id}/consultation/` | One per visit. `POST` starts it (and moves the linked `Queue` entry to `in_consultation` as a side effect); `PATCH` only while `status=in_progress`. |
| Complete consultation | `POST /visits/{id}/consultation/complete/` | Requires ≥1 diagnosis. Snapshots a `MedicalRecord`, closes the `Visit`, completes the `Queue` entry and linked `Appointment` (if any) — one transaction. |
| Diagnoses | `GET/POST /consultations/{id}/diagnoses/` | Only while the consultation is `in_progress`; at most one `primary`, any number of `differential`. |
| Medical records | `GET /patients/{id}/medical-records/` | Read-only — rows only ever appear via consultation completion. Access is itself audit-logged (CLAUDE.md §8 requires auditing "medical record access", not just its creation). |
| Lab test catalogue | `GET /lab/tests/` | Reference data — any authenticated user with `laboratory.view`. |
| Lab requests (order) | `GET/POST /consultations/{id}/lab-requests/` | How a diagnosis "triggers" a lab request — ordered from the consultation workspace. Only while the consultation is `in_progress`. |
| Lab requests (worklist) | `GET /lab-requests/`, `GET/PATCH /lab-requests/{id}/` | Flat, hospital-wide — a Lab Technician's queue. `PATCH status` only accepts `requested→sample_collected→cancelled`/`sample_collected→cancelled` (no skipping to `completed` directly). |
| Lab result | `GET/POST /lab-requests/{id}/result/` | `POST` requires `status=sample_collected`. `GET` hides the raw value from non-Lab-Technician roles until validated. |
| Lab result validation | `POST /lab-requests/{id}/result/validate/` | Moves the request to `completed`. |
| Medication catalogue | `GET /pharmacy/medications/` | `?search=` by name. |
| Prescription (issue) | `GET/POST /consultations/{id}/prescription/` | One per consultation, only while `in_progress`. |
| Prescription items | `GET/POST /prescriptions/{id}/items/` | Only while the owning consultation is `in_progress`. |
| Prescriptions (worklist) | `GET /prescriptions/`, `GET /prescriptions/{id}/` | Flat, hospital-wide — a Pharmacist's queue. |
| Dispense | `POST /prescriptions/{id}/items/{item_id}/dispense/` | Checks two ceilings: remaining on the prescription, and real stock (`InventoryItem.quantity_on_hand`, row-locked). Writes an `InventoryTransaction` as a side effect. |
| Inventory items | `GET/POST /inventory/items/`, `GET/PATCH /inventory/items/{id}/` | `?category=` `?low_stock=true`. `POST` (new catalogue entry) is Hospital-Admin-only per the RBAC matrix. |
| Stock movements | `GET/POST /inventory/items/{id}/transactions/` | `POST` checks `inventory.edit` explicitly (not the generic `create` mapping) — see docs/RBAC.md. `received`/`issued`/`adjusted`; rejects anything that would take stock below zero. |
| Suppliers | `GET/POST /inventory/suppliers/` | Reference data for `InventoryItem.supplier`. |
| Wards / rooms / beds | `GET/POST /admissions/wards/`, `/admissions/rooms/`, `/admissions/beds/` | Reference data. `?available=true` on beds excludes any bed with an active admission. `POST` is Hospital-Admin-only. |
| Admission (admit) | `GET/POST /visits/{id}/admission/` | One per visit. Rejects a bed that already has an active admission (the double-booking guard). |
| Admissions (worklist) | `GET /admissions/`, `GET /admissions/{id}/` | Flat, hospital-wide — defaults to currently-admitted only; `?status=discharged` to see history. |
| Transfer | `POST /admissions/{id}/transfer/` | Changes the bed after re-validating the new one is free. |
| Discharge | `POST /admissions/{id}/discharge/` | Creates the `Discharge` record and frees the bed. |
| Referrals (create) | `GET/POST /visits/{id}/referrals/` | Nested under the visit that prompted the referral. |
| Referrals (worklist) | `GET /referrals/`, `GET/PATCH /referrals/{id}/` | Flat, hospital-wide. `PATCH status` only accepts `pending→accepted→completed`, either state `→cancelled`. |
| Schema | `GET /schema/`, `/docs/` | drf-spectacular OpenAPI schema + Swagger UI. |

## Conventions

- All list endpoints paginated (`PageNumberPagination`, page size 25) — never
  return an unbounded list, per CLAUDE.md's low-bandwidth requirement.
- Default permission is `IsAuthenticated`; anything more permissive
  (like `/health/`) opts out explicitly, never the other way round.
